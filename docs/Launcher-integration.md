# Интеграция лаунчера и RU/EN

Реализован Windows-протокол из присланного GameApplication.cs. WebGL остаётся средством быстрых игровых тестов. Рекомендуемый релизный билд — Windows x64.

## Запуск

Отдельную сцену вручную добавлять не нужно. GameApplication создаётся до загрузки любой сцены через RuntimeInitializeOnLoadMethod, сохраняется между попытками и загружает Resources/GameApplicationSettings. После синхронной загрузки таблиц и подготовки шрифта запускаются обычные сценовые компоненты. Работает также прямое открытие GameScene в Editor.

- Windows: первый аргумент после EXE — один JSON, например `{"lang":"ru"}`. Дополнительные флаги Unity идут после него. Нет JSON, неверный JSON, отсутствующий/неподдерживаемый язык → en. Сохранённый язык этот выбор не переопределяет.
- Editor: начальный язык задаётся полем editorOverrideLang в Assets/Resources/GameApplicationSettings.asset. По умолчанию ru.
- WebGL: используется сохранённый язык, при отсутствии — en.
- Кнопки RU/EN меняют язык текущего процесса и сразу выполняют PlayerPrefs.SetString + Save. Новый запуск Windows снова применяет аргумент лаунчера.

## Результат сессии

| Действие | Windows | Editor / WebGL |
|---|---|---|
| Достигнут requiredLootBoxes | CompleteGame → код 3 | Сообщение о коде 3 и новая попытка |
| Выход из меню | LeaveGame → код 1 | Editor останавливает Play Mode; WebGL начинает новую попытку |
| Крестик окна / Alt+F4 | Код 1 | Не вызывает kernel32 |
| Смерть игрока | Повтор GameScene, процесс остаётся жив | Повтор GameScene |
| Restart | Повтор GameScene, язык сохраняется | То же |

При повторе после смерти/Restart GameApplication не пересоздаётся. Player, Enemy, NPC, состояние ящиков и менеджеры игровой сцены создаются заново. Порог победы читается из GameManager, в интеграции число 7 не зафиксировано.

Windows использует TerminateProcess из присланного решения. Значения протокола: 1 — досрочный выход, 3 — успешное прохождение, -1/0xFFFFFFFF — тестовая ошибка. Неожиданный код реальной аварии не означает успешного прохождения. Код лаунчера не должен считать любой ненулевой результат одинаковой ошибкой.

Принудительное завершение обходит OnApplicationQuit и финализаторы. Существующие настройки громкости/мыши/разрешения сохраняются в обработчиках изменений; язык сохраняется так же. Дополнительного обязательного сохранения при выходе не добавлено. Если позже появятся другие сохраняемые данные, сохранять их при соответствующем игровом событии.

Тестовый `auto` из файла издателя работает только в Windows Development: `{"lang":"en","auto":3}` завершит приложение примерно через две реальные секунды после инициализации. Разрешены 1, 3 и -1. В Release этот параметр игнорируется, метода имитации ошибки нет. Проверка на -1 не использует отрицательное значение как маркер «результат ещё не задан».

Окнами и фокусом ОС управляет лаунчер; код не добавляет переключение чужих окон. Обычное управление курсором Player/PauseManager остаётся в игре.

## Переводы и шрифт

- Закреплён пакет Unity Localization 1.5.13 и его зависимости.
- Assets/Localization/UI.asset — коллекция строк UI.
- Assets/Localization/Localization Settings.asset зарегистрирован в EditorBuildSettings как активные настройки пакета. Он нужен стандартному окну редактирования таблиц; вручную нажимать Create больше не требуется.
- Assets/Resources/Localization/UI Shared Data.asset — общие идентификаторы/ключи.
- UI_ru.asset / UI_en.asset в той же папке Resources — русские и английские String Tables.
- GameApplicationSettings.asset содержит ссылки на обе таблицы и исходный HomeVideo-Regular.ttf.
- LocalizedText назначен всем 14 TMP-надписям GameScene и подсказке в LootBox.prefab. Для двух динамических надписей Dropdown он меняет только шрифт; числовой список разрешений остаётся динамическим.

Используются штатные StringTable и SharedTableData, но небольшой синхронный LocalizationService читает их напрямую через Resources. Активные Localization Settings настроены для доступа к редактору таблиц; выбор языка игры по-прежнему выполняет LocalizationService. Он не использует глобальные Startup Locale Selectors, Addressables-каталог и LocalizeStringEvent. Это позволяет сразу загрузить две небольшие локальные таблицы, не добавлять загрузочную сцену и не зависеть от языка ОС.

Переводы хранятся по стабильным ключам, а не ищутся по исходному английскому тексту. При смене языка активные компоненты получают событие; скрытые подсказки/панели обновляются в OnEnable. После перезапуска сцены новые компоненты используют текущий язык. Подсказка interaction.open_loot подставляет обозначение Interact из Input System вместо фиксированной F.

TMP-атлас создаётся из исходного шрифта при инициализации и предварительно заполняется латиницей, русским алфавитом с Ё/ё, цифрами и пунктуацией. Включены дополнительные атласы для новых символов. Данные исходного TTF включены в билд. Все символы нынешних переводов проверены в cmap исходного шрифта; размер/вёрстку надписей ещё нужно проверить в реальном Player.

Добавление строки: добавить общий ключ с уникальным ID и значения с этим ID в обе таблицы, затем назначить ключ LocalizedText. У существующих переводов ID сохранять. Сейчас форматируется только именованный параметр {key} подсказки; Smart Strings/формы множественного числа для будущего HUD не заявлены реализованными.

### Редактирование текстов в Unity

1. Выйти из Play Mode. После обновления проекта закрыть старое окно Localization Tables, если оно было открыто до импорта настроек.
2. Открыть **Window → Asset Management → Localization Tables**.
3. Выбрать существующую коллекцию **UI**. Не создавать новую коллекцию и не заменять таблицы RU/EN.
4. Найти строку по ключу и изменить значения в колонках **ru** и **en**. Например, menu.resume — кнопка продолжения, interaction.open_loot — подсказка ящика. Сам ключ и ID сохранять.
5. Выполнить **File → Save Project**, затем проверить обе локали в Play Mode.

Текст на TMP-компоненте при включении перезаписывается значением из таблицы, поэтому редактировать нужно таблицу. `{key}` в подсказке подставляет обозначение клавиши Interact; сохранить этот параметр, если клавиша должна отображаться.

## Сборки

Открыть проект в Unity 6000.3.8f1, дождаться импорта пакетов. В меню **Game → Build** доступны:

- **Windows Release** → Build/Windows/Im3DTmp.exe;
- **Windows Development (launcher tests)** → Build/WindowsDevelopment/Im3DTmp.exe;
- **WebGL Development** → Build/WebGL.

Нужны соответствующие Unity Build Support modules. Скрипт берёт включённые сцены из EditorBuildSettings; сейчас это GameScene. Из командной строки редактора доступны `-executeMethod GameBuild.WindowsRelease`, `GameBuild.WindowsDevelopment` и `GameBuild.WebGLDevelopment`. Для пакетной сборки указать также projectPath, batchmode, quit и отдельный logFile; вернуть ошибку сборки скрипт обязан через исключение.

Издателю передаётся весь каталог Windows-билда, не один EXE. Ресурсы читаются стандартными путями Unity, от текущего рабочего каталога лаунчера не зависят. Работа launcher IPC через браузер не имитируется: WebGL проверяет игру/переводы, а не Windows exit codes.

## Проверки

1. Без Unity: `python3 -m unittest discover -s Tests -v` — проверка данных таблиц, ключей, подстановок, ссылок, компонента на каждом TMP-объекте, диапазона/уникальности ID и lockfile.
2. Unity Test Runner → EditMode → ApplicationTests: 16 случаев нормализации, JSON/fallback, наличия ресурсов/переводов, сохранения языка и активных настроек редактора с коллекцией UI. Тест сохранения восстанавливает старое пользовательское предпочтение после проверки.
3. После Windows Development-сборки, из PowerShell 7:

```powershell
./Tests/launcher-smoke.ps1 -Executable ./Build/WindowsDevelopment/Im3DTmp.exe
```

Сценарий запускает настоящий процесс с JSON одним аргументом и проверяет пять сценариев: коды 1/3/-1, неизвестный язык и неверный JSON. Для неверного JSON закрывает окно после инициализации и проверяет 1. Логи сохраняет во временном каталоге, указанном в конце. Выполнять с Development EXE; Release преднамеренно не поддерживает auto.

4. Отдельно запустить Release вообще без аргументов, проверить английский, закрыть окно и получить 1. Проверить, что auto=3 не завершает Release автоматически, затем выполнить игровую цель и получить 3. Проверить реальные меню Quit/Restart, смерть, повтор попытки, отображение обеих локалей и переключение языка при открытой паузе.
5. Повторить сценарии из настоящего лаунчера. Проверить его возврат на передний план, подписанное представление -1 и реакцию на реальную аварию.
6. Проверить WebGL и смену доступных разрешений. Предыдущая правка Dropdown включена: сохраняются ширина/высота, при открытии паузы пункт определяется заново; недоступный сохранённый режим заменяется текущим, затем 1920×1080 или первым доступным. Пустой список отключает Dropdown.

### Что проверено в облачной задаче

Семь Python-тестов данных пройдены. Проверено покрытие исходным шрифтом всех нынешних переводов. Изменённый C# отдельно скомпилирован для Windows Release/Development, Editor и WebGL с Unity 6000.3 reference assemblies, реальными TMP/Input System/UI DLL и временной заменой двух типов Localization API; это не полная сборка Unity. В четырёх скомпилированных вариантах выполнены проверки нормализации языка, наличия/отсутствия Windows API и auto, а также констант кодов. Native-завершение процесса при этих проверках не вызывалось.

Полный Unity-import, EditMode-тесты, Windows/WebGL-билды, запуск PowerShell-сценария, UI и настоящий лаунчер здесь не проверены: редактор в облаке не активирован, Windows нет. Кроме того, официальный tarball нового пакета перенаправляется на download.packages.unity.com, пока запрещённый текущим облачным прокси. Этот домен добавлен в сохранённый черновик сетевых настроек без удаления прежних разрешений; для применения в облаке нужны проверка/сохранение настроек и публикация среды. На обычной машине с доступом к Unity Package Registry это ограничение облачного прокси не действует.

Важные договорённости реализации: после смерти предлагаемый ранее повтор попытки сохранён; переключение языка в игре разрешено; присланный скрипт адаптирован под платформы при сохранении внешнего JSON/exit-code протокола. Эти решения и изменения Windows-выхода следует включить в проверку с издателем.
