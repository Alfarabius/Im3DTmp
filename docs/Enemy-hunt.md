# HuntState — охота на игрока

Изменение находится в ветке `polishing`. Логика обычных Chase/Attack и ранее согласованные механики ранений не менялись.

## Когда включается

- Через 10 секунд непрерывного Patrol, включая остановки для осмотра. Время настраивается в PatrolState → Time Before Hunting. При возвращении в Patrol таймер начинается заново.
- На 2-м, 4-м, 6-м и каждом следующем чётном открытом LootBox. Сигнал действует из Patrol, Chase, Attack и самого Hunt. Если он пришёл до завершения стартовой подготовки Enemy, вход в Hunt откладывается до готовности агента.
- Повторный сигнал во время Hunt начинает его заново и выбирает точку по текущей позиции Player. Если открытие ящика уже завершает игру победой, охота не запускается. Отключение победы по ящикам не отключает этот триггер.

У GameManager добавлено событие OnLootBoxOpened с числом открытых ящиков. Enemy подписывается при включении и отписывается при выключении.

## Что делает состояние

Enemy сбрасывает прежнюю цель, выбирает PatrolPoint, ближайший к текущей позиции Player, и бежит к нему со скоростью 5. Стамина остаётся неизменной: ни расхода, ни восстановления; даже при нулевой стамине скорость в Hunt не уменьшается.

Поиск использует прежние слои, радиус, угол зрения и проверки препятствий. Дополнительный фильтр допускает только Player. NPC не становятся целью в этом состоянии, даже находясь ближе игрока.

- Обнаружен Player в пределах AttackDistance → Attack.
- Обнаружен Player дальше AttackDistance → Chase.
- Точка достигнута без обнаружения Player → Patrol.
- Нет ссылки на Player/маршрут, точек или полного пути → возврат в Patrol.

Обнаружение Player проверяется раньше достижения точки. Hunt не отменяет физические столкновения/обход агентов, а только исключает NPC из выбора цели. После выхода в обычные Chase/Attack действует прежний выбор целей.

## Переключатель в Inspector

На Enemy появился компонент **Hunt State**:

- **Player Transform** — ссылка на корневой Transform Player. Для GameScene уже назначена через override экземпляра Enemy.
- **Run Speed** — 5 по умолчанию.
- **Update Patrol Point While Running** — нужная галочка. Выключена по умолчанию: точка фиксируется при входе. Включена: ближайшая к Player точка перевыбирается во время бега.
- **Point Update Interval** — период перевыбора, по умолчанию 0,3 с. Если ближайшая точка осталась прежней, повторный SetDestination не вызывается.
- **Arrival Tolerance** — допуск прибытия, по умолчанию 0,5 м; учитывается также stoppingDistance агента.

Маршрут берётся из существующего Route Root на PatrolState. Старое поле Player Transform и режим движения к игроку из PatrolState удалены; теперь у Patrol остаётся только таймер перехода в отдельный HuntState. Шрифты, локализация, настройки сборок и лаунчер не затрагивались.

## Проверки

`python3 -m unittest discover -s Tests -v` проверяет данные проекта и связи Hunt в prefab/scene.

Логику AI можно проверить без активированного Unity:

```sh
python3 Tests/EnemyHunt/run.py --unity-data /path/to/Unity/Editor/Data
```

Без `--unity-data` используются Mono и csc/mcs из PATH. Проверка компилирует реальные EnemyBrain, HuntState, PatrolState, ChaseState, AttackState и GameManager. Заменены только границы движка и завершение сессии. 27 сценариев проверяют таймер, чётные ящики, стартовую очередь, подписку/отписку, оба режима выбора точки, NPC-фильтр, видимость игрока, переходы, стамину и ошибочные маршруты.

Это не проверка нативного NavMesh/Physics/Animator. В Unity дополнительно проверить: триггеры на 2/4/6 ящиках, таймер при вращении Enemy, оба положения галочки при перемещении Player, бой с NPC в момент срабатывания триггера, прибытие к точке и возобновление обычного Patrol. Проигрывание и сборка здесь не запускались из-за отсутствия активированной лицензии Unity.
